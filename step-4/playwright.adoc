= Exploratory Testing with Playwright

One of the things QAs do all the time is executing exploratory testing to verify that everything works as expected, but relying on intuition, domain expertise, and creativity to uncover hidden defects and edge cases from a real user's perspective.

That's good and we still need to do it but, let machines do some of this work as they can navigate, and explore for us the web application.

Since this is a web application, we need to connect the code assistant to the browser so it can navigate through the website, verify that no erros are found, and so on.

In this case, we'll use Playwright to interact with the browser, and the Playwright MCP Server as a bridge between the LLM/Code Assistant and Playwright.

== Opening New Project

Close IBM Bob project, and `Open` a new one pointing to `galaxium-travels-playwright` placed in this workshop layout.

== Configuring Code Assistant

To configure IBM Bob to use the MCP Serever, go to `.bob` directory (it is already created and has salready ome content there), and create a `mcp.json` file with the following content:

[source, json]
----
{
  "mcpServers": {
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "@playwright/mcp@latest"
      ],
      "disabled": false,
      "alwaysAllow": [
        "browser_snapshot",
        "browser_click",
        "browser_type",
        "browser_close"
      ]
    }
  }
}
----

Then save the file, and the MCP server is configured and started.
You can verify it by going to MCP Servers section:

image::bobmcp.png[]

Now, we can start prompting the Code Assistant to do a exploratory test plan.

IMPORTANT: Before executing any prompt read the two following sections. They use extensively tokens (around 11 IBM Bob coins per execution). To save some coins, you can try to modify the prompts to squash the generation of the test plan and the implementation of the test plan into one execution.

== Exploratory Test Plan

Let's start by asking to create a test plan:

[quote, IBM BOB]
----
You are an expert tester, and you need to do some exploratory testing plan of my web application hosted at http://localhost:5173/

The application is a webpage to book intergalactic trips, so you can expect flights, bookings, different kind of trips such as economy, business, ... and also booking extras such as heavy luggage.

When you need to login to the system use the username Alice and the email alice@example.com as password/email.

Your mission is to act as a user of the system that wants to book a new flight.

Use the Playwright MCP to access the web application.

You ONLY need to create a testing plan with as much information as possible, so it can be used later by a human, but also to generate automatic tests using Playwright code.
----

Notice that I am giving a lot of context so even though we expect some freedom, we also want system executes things more or less deterministic and with some meaning.

When you execute the prompt, notice that a browser is started, keep it open but in a side, and always keep an eye to the Code Assistant chat as it might ask you to approve MCP operations.
If you don't approve it, the execution is paused and no activity happens.

image::bobapprove.png[]

After some minutes, and watching browser doing things automatically, we end up with a exploratory testing plan file explaining all the steps that you can execute, and some open questions that could be addressed.

== Implementing Test Plan

For now, let's leave the test plan as is, of course we could get the feedback of the Code Assistant and ask to improve it even more, but for the sake of simplicity, let's ask Code Assistant to implement the exploratory test.

WARNING: This step consumes a lot of tokens. You can skip it if you only have some tokens remaining to execute the last example of the workshop.

[quote, IBM BOB]
----
You are an expert Java developer that knows how to write Playwright tests.

Implement only the exploratory test plan created in the previous step using the Playwright Java framework and following the best practices such as PageObjects pattern.
The project already have the Playwright dependency registered, so the version is fixed and doesn't need to change, or configure anything.

Use the Plywright MCP to execute and get any runtime information you need to genereate the test, and also use the the playwright-java skill to find the best practices before implementing anything with Playwright Java. 
----

After the prompt execution, Code Assistant has created all the Playwright classes required to implement the tests. 

Now, it is time to ask Code Assistant to implement any of the test case. 
Notice that this step might not be required if it has condensed the creation of classes and the tests into a single step.
Just follow the AI conversation.

[quote, IBM BOB]
----
Can you code the smoke test classes using previous implemented classes?
----

After some minutes, we'll have all the smoke tests for the application implemented using all the infrastructure classes created previously.
